IndiLogs 3.0

HP Indigo Digital Press Log Analysis Tool

.NET 10.0 WPF + SkiaSharp MVVM Architecture C# Latest

Overview

IndiLogs 3.0 is a WPF desktop application for analyzing log files from HP Indigo digital presses. It processes ZIP archives containing PLC logs, APP logs, configuration files, screenshots, chart data, and more — providing powerful filtering, coloring, searching, charting, and analysis tools.

13 Analysis Tabs

PLC, APP, Events, Screenshots, Config, DB/Terminals, Setup Info, Globals, Systab, Charts, CPR, Step Recorder, Different Logs

Advanced Filtering

Boolean search (AND/OR/NOT), filter trees, thread filters, logger tree, time ranges, filter out with undo

Interactive Charts

SkiaSharp-rendered line charts, Gantt charts, state timelines, signal browser with zoom/pan/measure

CPR Analysis

10 graph types for Color Patterning & Registration analysis with station comparison and DFT

Global Grep

Multi-location search across file systems and ZIP archives with scheduled searches and email notifications

Plugin System

Extensible log format support via ILogFilePlugin interface with 5 built-in parsers (CSV, JSON, Log4Net, etc.)

UI Layout

The main window is organized into distinct areas: a toolbar at the top, collapsible side panels, a center content area with 13 tabs, and a status bar.

Loading Files

IndiLogs accepts ZIP archives from HP Indigo digital presses. There are two configuration types:

S4-5 Configuration

ZIP contains a binary APP file. Features: IO Terminal data, EM Statistics Gantt, AXIS/CHSTEP components for chart export. Systab tab available.

S6 Configuration

APP is not binary (text format). Features: State analysis, PLC state transitions. Different parsing pipeline.

How to Load

  • Open Button — Click the OPEN button in the toolbar to browse for ZIP files
  • Drag & Drop — Drag ZIP files directly onto the main window
  • Multi-session — Load multiple ZIPs; switch between them in the Explorer panel
  • Tab Pre-selection — After loading, a dialog lets you choose which tabs to populate (deferred parsing for faster load)

The loading dialog shows an animated spinner with progress percentage. Files are parsed in the background with parallel processing.

Tab: Events

System events extracted from the session. Auto-generated columns with 24px row height. Status bar shows event count. Events can be filtered by the global time range filter.

Tab: Screenshots

Extracted screenshot images from the ZIP archive. Displayed in a scrollable grid with zoom control via mouse wheel (Ctrl+Plus/Minus).

Tab: Config

Read-only view of the press configuration file in JSON/text format. Part of the ConfigExplorerViewModel which also includes a database browser for SQLite tables and columns.

Tab: DB & Terminals

Shows setup information and terminal data. For S4-5 configurations, this includes IO Terminal CSV data from devices like BIM, ECM, PDC. The ConfigExplorer provides a tree-based database browser with search.

Tab: Setup Info

Displays press configuration from the Readme file in the ZIP. Shows machine name, press type, serial number, software version, and IP address. Used for quick identification of the press being analyzed.

Tab: Globals

Press global variables parsed from XML. Features:

  • File selector — Dropdown to choose between globals files
  • Search bar — Filter by parameter name with clear button
  • Diff toggle — "DIFF ON" button shows only entries where Value differs from Default
  • Columns: Name, Value, Default, IsRelevant
  • Virtualized for performance with large datasets

Tab: Systab

S4-5 only System tables with a split view:

  • Left panel — TreeView of topics (collapsed). Shows item counts and asterisk (*) for entries with differences from default values
  • Right panel — DataGrid with columns: Parameter, Saved, Default, Minimum, Maximum
  • Rows with differences are highlighted yellow
  • "Diffs Only" checkbox to filter to changed parameters
  • Search bar to find specific parameters

Tab: Charts

Interactive charting powered by SkiaSharp. Supports multiple chart types with pan, zoom, and measurement tools.

Line/Signal Chart (ChartGraphView)

Multi-series line chart with dual Y-axes. Rendered with SkiaSharp for high performance.

  • Multiple signals — Each series assignable to left (L) or right (R) Y-axis
  • Reference lines — Horizontal/vertical dashed lines with labels and custom colors
  • State intervals — Semi-transparent background regions showing machine state changes (STANDBY, PRINT, etc.)
  • Thread markers — Vertical dashed lines with thread names and 6 distinct colors
  • Time gaps — Red semi-transparent overlay showing periods with no data
  • Event markers — Red dots with tooltips for system events/alarms
  • Smoothing — Moving average filter (window=10) to reduce noise

Gantt Chart (ChartGanttView)

Horizontal timeline showing state intervals as colored bars. Each component/channel gets its own row (24px height).

  • State colors — 10 distinct colors for CHSTEP states (teal, red, green, orange, purple, blue, pink, brown, blue-grey, lime)
  • Hover tooltips — Show state name and duration
  • Click-to-filter — Click a state bar to filter the time window
  • EM Statistics — Optional independent timeline from EM_Statistics.csv
  • Cursor sync — Red vertical line synchronized with other chart views

Signal Browser (ChartSignalList)

Categorized signal browser for adding signals to charts:

Chart Interaction

  • Pan — Click and drag to move the view
  • Zoom — Mouse wheel to zoom in/out

  • Cursor sync — Cursor position synchronized across all chart views

Chart from Pattern (Graph per Demand) New

Create a chart from any log line by extracting values with a regex pattern. Right-click a log row and select "Create Chart from Pattern..." to open the pattern dialog.

How It Works

  1. Right-click any row in the PLC Logs or APP Logs grid
  2. Select "Create Chart from Pattern..." from the context menu
  3. The dialog shows the original message. Click Auto-Detect to generate a regex pattern automatically
  4. The auto-detect prioritizes key=value patterns — it finds the last =number in the message and builds a capture group for the value
  5. Edit the regex if needed — a live preview shows the captured value from the original message
  6. Choose the search field (Message, Logger, or ThreadName)
  7. Optionally include machine state to show state transitions as a Gantt track alongside the chart
  8. Click Create Chart — all logs are scanned in a background thread, values extracted, and the chart appears in the Charts tab

Supported Value Types

TypeDetectionChart StyleExample
NumericCaptured group parses as a numberAnalog line chartTemp: 25.3 C → pattern Temp:\s*(-?\d+\.?\d*)
BooleanCaptured group is True/FalseDigital (0/1) chartValve: True → pattern Valve:\s*(True|False)

Auto-Detect Examples

MessageAuto-Generated PatternCaptured Value
Engage Rear DiffPosition =-37Engage\ Rear\ DiffPosition\ \=\s*(-?\d+\.?\d*)-37
IO_Mon: Pressure = 1013.5 barIO_Mon:\ Pressure\ \=\s*(-?\d+\.?\d*)1013.5

Tips

  • The pattern must contain at least one capture group (...) — the first group is used as the chart value
  • For key=value messages, auto-detect picks the last =number pair (the most specific value)
  • Machine state is parsed from S6 PlcMngr: STATE1 -> STATE2 transitions or S4-5 ==== STATE_XXX - Enter patterns
  • Extraction runs on a background thread — large log sets (millions of rows) are handled without freezing the UI

Search & Navigation

Press Ctrl+F to open the floating search panel (top-right of the content area).

  • Simple search — Type text to filter across Message + ExtraFields
  • Boolean operators — Use AND, OR, NOT for complex queries
  • Syntax validation — Invalid queries show error tooltip; search only applies boolean mode when operators are detected
  • 250ms debounce to avoid UI lag during typing
  • Press Esc to close the search panel

Example Queries

motor AND error
temperature OR pressure
NOT debug
(error OR warning) AND motor NOT routine

Filtering

The filtering system is the core of IndiLogs. Multiple filter types work together in a pipeline:

Filter Pipeline (in order)

  1. Advanced Filter Tree — AND/OR/NOT nodes with conditions (field, operator, value)
  2. Thread Filters — Multi-select thread names (separate lists for PLC and APP)
  3. Logger/Method Filters — APP only, filter by logger name or method
  4. Logger Tree Filters — Show-only or hide entire logger branches
  5. Search Text — Always-on contains search (or boolean expression)
  6. Global Time Range — DateTime start/end applied across all tabs
  7. Negative Filters (Filter Out) — Applied last, removes matching entries

Filter Condition Operators

OperatorDescription
EqualsExact match
ContainsSubstring match
Begins WithStarts with value
Ends WithEnds with value
RegexRegular expression (2s timeout for safety)

Filter Out

Negative filtering — excludes matching entries from results. Applied after all include filters.

  • Add — Select text in a log message, right-click > Filter Out. Adds the text to the negative filter list.
  • Thread filter out — Right-click > Filter Out Thread to exclude by thread name
  • Undo — Ctrl+Z undoes the last filter out (LIFO undo stack)
  • Toggle — "APPLY FILTER OUT" checkbox in the bottom bar enables/disables all negative filters at once
  • Separate negative filter lists for PLC and APP tabs

Coloring Rules

Apply custom colors to log rows based on field conditions. Each session can have its own coloring rules.

How It Works

  1. Click Color Rules in the bottom bar to open the Coloring Window
  2. Add rules: choose a Field (Message, Level, Thread, etc.), Operator (Contains, Equals, Regex), Value, and pick a Color
  3. Rules are applied in parallel (Parallel.ForEach) for performance
  4. Colors are frozen WPF Brushes — shared across all matching LogEntry objects to save memory

Coloring Example

Level = ERRORMotor controller error code 0x4F
Level = WARNWeb tension exceeding threshold
Message contains "state"State transition: STANDBY -> GET_READY
Message regex "Job_\d+"Print job started: Job_2025_001

Default vs Session Rules

  • User defaults — UserDefaultMainRules / UserDefaultAppRules applied when no session-specific rules exist
  • Session rules — MainColoringRules / AppColoringRules override defaults for the active session
  • Compiled Regex — Patterns used in coloring rules are compiled (RegexOptions.Compiled) for hot-path performance
  • Cached regex — ConcurrentDictionary<string, Regex> prevents re-compilation

Time Range Filtering

Three time-based filtering mechanisms:

Global Time Range

Click Time Range in the bottom bar to open a DateTime picker. Set start and/or end times to filter all tabs (PLC, APP, Events) simultaneously.

Status bar shows: "Time Range Filter: PLC=X, APP=Y, Events=Z"

The filter uses the min/max timestamps from both PLC and APP caches for picker bounds.

Context Time Focus

Right-click a log entry > Filter Context. Shows all logs within ±N seconds/minutes around the selected entry.

The context window size is configurable (ContextSeconds property). Useful for investigating what happened around an error.

Range Selection

Two-step selection process:

  1. Start Range — Select a log entry and mark it as range start
  2. End Range — Select another entry to close the range

All logs between the two markers are shown. Uses List<T>.GetRange() for efficiency (not LINQ Skip/Take). Shows count and time window in status.

Time Sync

Synchronizes scrolling between PLC and APP tabs using timestamps. Toggle with the Sync button in the toolbar.

How It Works

  • Binary search — Finds the nearest log entry at the target time (O(log N))
  • Clock conversion — PLC and APP may run on different clocks. TimeSyncOffsetSeconds (double precision) adjusts for drift
  • SyncedTime — Each PLC LogEntry stores an APP-clock timestamp for tick-precision correlation
  • 60-second max distance — If no log within 60 seconds, sync is skipped
  • Tab-aware — Sync is applied when switching between PLC and APP tabs
  • Chart sync — Charts cursor position can also sync with log views

Marking & Annotations

Marking

  • Press Space to mark/unmark the selected row (light green background)
  • Next/Previous Marked buttons in toolbar to navigate between marks
  • Open Marked Lines window to see all marked entries (PLC and APP can be combined or separate)
  • Marked rows show as green ticks in the heatmap sidebar

Annotations

  • Right-click a log entry > Add Annotation
  • Each annotation stores: time, author, text
  • Show All Annotations toggle in toolbar — persistent display vs hover-only
  • Annotation icon indicator in the first column (APP logs)
  • Annotations are saved with case files

Logger Tree

The left panel's "Loggers" tab shows a hierarchical view of all loggers, built from dot-notation names (e.g., com.hp.logger.subsystem).

Separate tree filters exist for PLC loggers (PlcLoggerTreeRoot) and APP loggers (LoggerTreeRoot).

Global Grep

Multi-location search across file systems, ZIP archives, and loaded sessions.

Features

  • Structured criteria — AND/OR condition groups for complex searches
  • Streaming results — Background threads enqueue results; UI timer flushes them in batches
  • Multiple locations — Search across network paths, local folders, SMB shares
  • Profiles — Save and load search criteria + locations
  • Scheduled searches — Recurring searches with Windows Task Scheduler integration
  • Email notifications — Send search results via email (SMTP with DPAPI-encrypted credentials)
  • HTML reports — Export search results as formatted reports
  • Cancellation — Cancel mid-search with CancellationToken

Export & Reports

Export log data and chart data to CSV files with configurable presets.

Export Options

  • PLC + APP logs with selected columns
  • Events data
  • Machine state transitions
  • IO Terminal data S4-5 — Merged from Io-*.csv files
  • EM Statistics S4-5 — Gantt timeline data
  • Log statistics — Distribution tables
  • Unix timestamps — Optional inclusion

Chart Export

Two modes: In-memory transfer to the Charts tab (no file I/O) via ChartDataTransferService, or CSV file export for external tools.

Cases & Configurations

Cases

Save the current analysis state as a "case file" that includes all filters, coloring rules, marked logs, and annotations. Load cases to restore previous investigation states.

Saved Configurations

Save and load filter/coloring snapshots from the right panel. Double-click a saved config to apply it instantly.

  • Save Current — Snapshot current filter + coloring state
  • Load Selected — Apply saved configuration
  • Show Folder — Open %AppData%\IndiLogs3.0\Configs\
  • Delete Selected — Remove saved configuration

Live Monitoring

Real-time log monitoring by polling external servers. When active, the toolbar shows Resume/Pause/Clear buttons.

  • ▶ RESUME — Continue polling for new entries
  • ⏸ PAUSE — Pause polling (keeps current data)
  • ⛔ CLEAR — Clear all live data
  • Color rules apply in real-time
  • Configurable polling interval

Compare

Side-by-side log comparison between sessions. Features synchronized scrolling, diff highlighting, and time-range alignment.

Analysis Tools

Access via the Analysis toolbar button or the left panel menu. S4-5 goes directly to Statistics. S6 shows a menu to choose Failures or Statistics.

Chart from Pattern (Graph per Demand) New

Create instant charts from any log line by extracting values with a regex pattern. Available via right-click context menu on both PLC and APP log grids.

Workflow

  1. Right-click any row in the PLC Logs or APP Logs grid and select "Create Chart from Pattern..."
  2. The dialog shows the original message content. Click Auto-Detect to auto-generate a regex extraction pattern
  3. Auto-detect finds the last =value pair in the message and creates a capture group for the number — ideal for log formats like DiffPosition =-37 or Monitor.s = 486799
  4. Optionally edit the regex, choose which field to search (Message, Logger, ThreadName), name the chart, and toggle machine state inclusion
  5. Click Create Chart — all logs are scanned on a background thread and the chart appears in the Charts tab

Numeric Values

Captured values that parse as numbers become an Analog line chart. Examples: temperature, pressure, position offsets, counters.

Boolean Values

True/False captures become a Digital (0/1) chart. Useful for valve states, enable flags, sensor statuses.

Machine State Overlay

Optionally includes a Gantt state track (S6: PlcMngr: A -> B, S4-5: ==== STATE - Enter) alongside the signal chart.

Auto-Detect Intelligence

Prioritizes key=value patterns. Picks the last =number in the message, escapes the prefix, and inserts \s*(-?\d+\.?\d*).

MVVM Pattern

Rules

  • Views contain ZERO business logic — only XAML + minimal code-behind for UI plumbing
  • ViewModels never reference concrete Window types — use IViewFactory.Create<T>()
  • ViewModels never call MessageBox.Show() — use IDialogService
  • Services are stateless or singleton — all dependencies injected via constructor
  • No Dispatcher.Invoke (blocking) — only Dispatcher.InvokeAsync or BeginInvoke

Base Classes

ClassPurpose
ViewModelBaseBase for all VMs. Provides OnPropertyChanged() with CallerMemberName and SetField()
RelayCommandICommand implementation for binding commands to UI controls

Dependency Injection

Manual DI via Bootstrapper.cs — no external container (Autofac, Unity, etc.).

        Resolve<IPluginLoader>(),

}

Performance Optimizations

StringPool

Thread-safe string interning during parsing. Deduplicates repeated logger names, thread names, etc.

Frozen Brushes

Static, frozen WPF Brush instances shared across all LogEntry objects. Level-based tint brushes (8% alpha).

Parallel Processing

Parallel.ForEach for log coloring. PLINQ AsParallel().AsOrdered() for filtering chains.

Batch UI Updates

ObservableRangeCollection.AddRange() with 500-item batches (AppConstants.UiUpdateBatchSize).

Compiled Regex

RegexOptions.Compiled for hot-path patterns. Cached in ConcurrentDictionary.

Memory-Mapped Files

ChartDataService uses MMF for large CSV files — no full memory load required.

Deferred Parsing

Nested ZIP data not loaded until user opens the tab. TerminalCsvBytes stored as byte[].

Binary Search

Time-sync uses O(log N) search for nearest log at target time.

ConfigureAwait(false)

All service-layer async methods skip UI context marshaling.

GetRange() over Skip/Take

List<T>.GetRange() for range filtering — avoids LINQ enumerator overhead.

Lazy Chart Signals

SignalData stores sparse points; dense array materialized on first access with forward-fill.

HashSet Lookups

O(1) thread/logger filter membership checks instead of O(N) list contains.

FrozenSet / FrozenDictionary New

Immutable, read-optimized collections for static lookup tables: state colors, field maps, file extensions, error levels, public key tokens.

Cached Compiled Regex New

FilterNode and SearchCondition cache compiled regex per pattern. Eliminates per-entry recompilation during filtering and grep operations.

ThreadStatic Buffers New

ChartDataService uses [ThreadStatic] byte buffers instead of per-call allocations. Zero GC pressure in tight CSV parsing loops.

Zero-Alloc String Search New

StringComparison.OrdinalIgnoreCase replaces .ToLower().Contains() across all search/filter code — no intermediate string allocations.

Centralized Constants New

Shared AppConstants.BuiltInFields and AppConstants.ErrorLevels as FrozenSets — eliminates 5+ duplicate HashSet definitions.
